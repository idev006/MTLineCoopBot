# เทมเพลต Dashboard KPI ของทีม (Metrics Dashboard Template)

> อ้างอิง: [บทที่ 8.3 กระบวนการพัฒนา](./ch-08-process.md) · สร้างอัตโนมัติด้วย `app/Dashboard.js` (รัน `createDashboard()` ใน Apps Script Editor)

## วิธีสร้าง Dashboard

```text
1. เปิดไฟล์ Google Sheets โครงการ (ไฟล์เดียวกับ t_member_mast)
2. เปิด Apps Script Editor → เลือกฟังก์ชัน createDashboard → Run
3. ระบบจะสร้าง 5 แท็บพร้อมสูตร KPI ข้อมูลตัวอย่าง และกราฟ Burndown
```

หรือสร้างมือตามโครงสร้างด้านล่าง

## โครงสร้าง Workbook (5 แท็บ)

### 1. 📊 KPI — ภาพรวมตัวชี้วัด (บทที่ 8.3.2)

| แถว | KPI | สูตร (Google Sheets) | เป้าหมาย |
|-----|-----|----------------------|----------|
| 5 | อัตราเสร็จงานต่อสัปดาห์ | `=COUNTIFS('Card Log'!$A:$A,">="&(TODAY()-7),'Card Log'!$E:$E,"Done")` | ≥ 2–3 |
| 6 | WIP เฉลี่ย | `=IF(COUNT('🔢 WIP & Cycle'!$B$2:$B$500)=0,"",ROUND(AVERAGE('🔢 WIP & Cycle'!$B$2:$B$500),2))` | ≤ 3 |
| 7 | งานค้าง (Backlog) | กรอกมือสัปดาห์ละครั้ง (จาก KANBAN.md) | ลดลงต่อเนื่อง |
| 8 | Cycle Time (วัน) | `=IF(COUNT('🔢 WIP & Cycle'!$G$2:$G$500)=0,"",ROUND(AVERAGE('🔢 WIP & Cycle'!$G$2:$G$500),1))` | ≤ 5 |
| 9 | ความถูกต้องตามเอกสาร | `=IF(COUNTA('✅ DoD Log'!$C$2:$C$500)=0,"",COUNTIF('✅ DoD Log'!$C$2:$C$500,"✅")/COUNTA('✅ DoD Log'!$C$2:$C$500))` | 100% |

**คอลัมน์:** KPI | ค่าปัจจุบัน (สูตร) | เป้าหมาย | สถานะ (✅/⚠️ อัตโนมัติ) | หมายเหตุ

- สถานะอัตโนมัติ เช่น `=IF(ISNUMBER(B5),IF(B5>=2,"✅","⚠️"),"")`
- B2: `=TODAY()` แสดงวันอัปเดตล่าสุด

### 2. Card Log — บันทึกการเคลื่อนการ์ด (แหล่งข้อมูลหลัก)

| คอลัมน์ | ความหมาย |
|---------|----------|
| A วันที่ | วันที่ย้ายการ์ด |
| B Card ID | เช่น MT-08 |
| C เรื่อง | ชื่องานสั้นๆ |
| D จาก / E ไป | สถานะ: Backlog · To Do · In Progress · Done |
| F เอกสารอ้างอิง | บท/หัวข้อในเอกสารเล่ม |
| G ผู้ทำ | เจ้าของการ์ด |
| H หมายเหตุ | เช่น "DoD ครบ" |

> ทุกครั้งที่ย้ายการ์ดใน KANBAN.md ให้เพิ่มแถวใน Card Log ด้วย — KPI จะคำนวณให้อัตโนมัติ

### 3. 📈 Burndown — แผน vs จริงรายสัปดาห์

| คอลัมน์ | ความหมาย |
|---------|----------|
| A สัปดาห์เริ่ม | วันที่เริ่มต้นสัปดาห์ |
| B งานที่วางแผน | จำนวนการ์ดที่วางแผนเสร็จในสัปดาห์ |
| C งานที่ทำเสร็จจริง | จำนวนที่เสร็จจริง |
| D สะสมตามแผน | `=SUM($B$2:B{r})` |
| E สะสมจริง | `=SUM($C$2:C{r})` |

- กราฟเส้นถูกสร้างอัตโนมัติ (สะสมตามแผน vs สะสมจริง)
- เส้นจริงอยู่ต่ำกว่าเส้นแผน = งานเร็วเกินกำหนด / สูงกว่า = งานล่าช้า

### 4. 🔢 WIP & Cycle — WIP รายวัน + Cycle Time ต่อการ์ด

**ส่วน A–B (WIP รายวัน):** วันที่ | จำนวน In Progress — บันทึกทุกวันทำการ

**ส่วน D–G (Cycle Time ต่อการ์ด):**
| คอลัมน์ | ความหมาย |
|---------|----------|
| D Card ID | รหัสการ์ด |
| E เริ่ม (To Do) | วันที่ย้ายเข้า To Do |
| F เสร็จ (Done) | วันที่ย้ายเข้า Done |
| G Cycle (วัน) | `=IF(AND(ISNUMBER(E{r}),ISNUMBER(F{r})),F{r}-E{r},"")` |

### 5. ✅ DoD Log — ตรวจ Definition of Done (บทที่ 8.1.3)

| คอลัมน์ | ความหมาย |
|---------|----------|
| A Card ID / B เรื่อง | ระบุการ์ด |
| C DoD ครบ (อัตโนมัติ) | `=IF(AND(D{r}="✅",E{r}="✅",F{r}="✅"),"✅","❌")` |
| D เอกสารอัปเดต | ✅/❌ |
| E Contract test ผ่าน | ✅/❌ |
| F README อัปเดต | ✅/❌ |
| G หมายเหตุ | |

> DoD เต็มรูปแบบมี 6 ข้อ (บทที่ 8.1.3) — ตารางนี้เก็บ 3 ข้อหลักสำหรับการตรวจอัตโนมัติ

## แนวปฏิบัติประจำสัปดาห์

1. **ทุกวันทำการ:** บันทึก WIP ในแท็บ WIP & Cycle
2. **ทุกครั้งที่ย้ายการ์ด:** เพิ่มแถวใน Card Log + อัปเดต KANBAN.md
3. **ทุกสัปดาห์ (ประชุมวางแผน 15 นาที):** กรอก Burndown + Backlog count ใน KPI → ทบทวน KPI ว่าเข้าเป้าหรือไม่
4. **เมื่อปิดการ์ด:** กรอก Cycle Time + DoD Log แล้วตรวจว่า DoD ครบ 6 ข้อก่อนย้ายไป Done

- `app/docs/KANBAN.md` — บอร์ดงานทีม (ข้อมูลการ์ด)
- `app/docs/ch-08-process.md` — กระบวนการและ KPI
